# ClarIT — Project Documentation

## 1. Project Purpose

ClarIT is an Information Technology Help Desk artificial intelligence chatbot web application. It is designed to act as a virtual first-line support agent that helps users diagnose and resolve common Information Technology issues such as Wi-Fi connectivity problems, password recovery, printer failures, slow computer performance, suspected virus infections, email attachment errors, and other day-to-day technology problems. The application allows users to describe their issue in natural language and receive structured, step-by-step troubleshooting guidance generated by an artificial intelligence model that has been instructed with a curated knowledge base of professional Information Technology diagnostic rules.

The application is intended for several user groups. The primary users are everyday employees, students, and members of the general public who require immediate assistance with technology issues but do not have direct access to a human Information Technology technician. The secondary users are small Information Technology support teams who can use ClarIT as a triage tool to reduce the number of basic, repetitive support requests they receive, allowing them to focus on more complex problems. The tertiary users are organizations who wish to provide a self-service support channel that is available at any time of day without requiring additional staffing.

The overall goal of the project is to provide a fast, professional, and accessible interface where users can receive trustworthy Information Technology guidance without having to search through documentation, wait in support queues, or escalate issues unnecessarily. The system focuses on clarity, response speed, conversation continuity, and a clean visual experience that works equally well on mobile devices, tablets, and desktop computers.

## 2. System Architecture

ClarIT is built using a layered architecture that cleanly separates the user-facing interface, the application server, the artificial intelligence processing layer, and the persistent data storage layer. This separation makes the system easier to maintain, debug, and extend, while also allowing each layer to be optimized independently. The system is composed of four main components that communicate over standard network protocols, and all components are designed to operate efficiently within the Replit hosting environment.

The first component is the frontend client, which is a single-page application written in React and built with Vite. The client is responsible for rendering the user interface, managing local interaction state, and communicating with the backend through standard Hypertext Transfer Protocol requests. The second component is the frontend server, implemented as a thin Express application written in TypeScript. This server hosts the Vite development middleware in development mode, serves the static production build in production mode, and acts as a transparent reverse proxy for any request whose path begins with the prefix `/api`. All such requests are forwarded directly to the Python backend without any buffering, which is essential for the proper streaming of artificial intelligence responses through Server-Sent Events.

The third component is the Python backend, implemented as a Flask application that runs on a separate internal port. The Python backend is the authoritative source of business logic and is responsible for managing conversations, persisting messages, and communicating with the artificial intelligence provider. It uses the psycopg2 library to communicate with the PostgreSQL database and the official OpenAI Python software development kit to communicate with the artificial intelligence model. The fourth component is the persistent storage layer, which is a managed PostgreSQL database provided by the Replit platform. The database stores conversations and individual chat messages, and is accessed through a standard connection string supplied by the platform through an environment variable.

The data flow through the system is straightforward. When a user submits a message, the React client sends a request to the local Express server, which immediately forwards the request to the Python backend. The Python backend constructs a complete conversation payload consisting of the system instructions, the prior conversation history, and the new user message, and then opens a streaming connection to the artificial intelligence provider. As tokens are received from the artificial intelligence provider, they are immediately written back to the client through the streaming connection, passed through the Express proxy without buffering, and rendered into the user interface in real time. In parallel, the user message and the final assistant response are persisted to the PostgreSQL database so that the conversation can be retrieved later.

## 3. Conversation Flow Design

The conversation flow has been carefully designed to feel immediate, natural, and continuous, while also providing accurate and structured Information Technology guidance. When a user first opens the application, they are presented with a welcome screen that displays a friendly greeting, a short description of the assistant, and a set of suggested issue prompts such as "My Wi-Fi keeps disconnecting" or "I forgot my password." These suggestions allow the user to start a conversation with a single click, even if they are unsure how to phrase their issue.

Once the user submits a message, either by clicking a suggestion or by typing their own description, the interface immediately appends the user's message to the visible conversation and displays an animated loading indicator beneath it. This indicator confirms that the request has been received and that the assistant is preparing a response. At the same moment, the frontend opens a streaming connection to the backend, which in turn opens a streaming connection to the artificial intelligence provider. As soon as the artificial intelligence model produces its first token, the placeholder loading indicator is replaced with the streaming response, which appears progressively word by word as it is generated.

In parallel with the streaming response, the system performs background persistence operations. If the conversation is new, the backend creates a new conversation record and assigns it a generated unique identifier and a title derived from the first user message. The user message is then stored in the chat messages table linked to that conversation. Once the streaming response is fully completed, the assistant message is also stored in the chat messages table. These persistence operations do not block the streaming response, which means the user always sees the assistant typing in real time, even when the database operations are still in progress.

Conversation continuity is fully supported. Each user is identified by a session identifier that is generated and stored in the browser the first time the user visits the application. All conversations created by that browser are associated with the session identifier, and the user can return to the application at any time and see a list of all of their previous conversations in the sidebar. Selecting a previous conversation loads its full message history from the database and allows the user to continue the conversation as if it had never ended. Users may also delete a conversation, which removes both the conversation record and all of its associated chat messages from the database. The assistant is instructed to remain strictly within the Information Technology support domain, to provide concise and practical step-by-step guidance, to warn the user before suggesting any potentially risky action, and to recommend escalation to a human technician after three unsuccessful troubleshooting attempts.

## 4. User Interface Design

The user interface of ClarIT is designed to be clean, modern, and immediately understandable, with a strong emphasis on professional presentation and a smooth experience across all device sizes. The application is structured around two primary regions on larger screens. The first region is a fixed sidebar on the left side of the screen, which contains a prominent "New Chat" action button and a scrollable list of all of the user's previous conversations. The second region is the main chat panel on the right side of the screen, which contains the conversation area, the loading indicators, the suggestion buttons for new chats, and the message composer at the bottom.

On tablet and mobile screens, the layout adapts automatically. The sidebar is hidden by default, and a small menu button appears in the upper left corner of the screen. Tapping this button slides the sidebar in from the left as an overlay, while a translucent backdrop is rendered over the chat area to indicate that the sidebar is now the active surface. Tapping the backdrop, tapping the close icon, selecting a conversation, or starting a new chat will automatically dismiss the sidebar so that the chat area can take the full width of the screen. The composer at the bottom of the chat panel also adapts on small screens, with the text input and the send button stacking vertically when there is not enough horizontal space to display them side by side.

The visual design uses a calm and professional color palette built around a strong primary blue, soft neutral grays, and a clean white background. The typography is set in the Montserrat font family for a modern and legible appearance. User messages are rendered as filled blue bubbles aligned to the right side of the chat area, while assistant messages are rendered as outlined white cards aligned to the left side, with markdown formatting fully supported so that headings, lists, code blocks, and emphasis are displayed correctly. Loading indicators are rendered as three animated dots inside an empty assistant bubble, and a top-level navigation bar at the top of the page displays the ClarIT brand logo, a "Chat" link to the chat view, and a "Notes" link to a supporting documentation page.

The application is composed of three primary screens. The first is the chat screen, which is the main entry point of the application and contains the sidebar and chat panel described above. The second is the welcome state of the chat screen, which is shown when no conversation is currently selected and which displays the suggested prompts and the assistant introduction. The third is the notes screen, which is a separate page used to display structured project documentation and reference material. A standard not-found page is also provided to handle requests for any unknown route.

## 5. Technology Stack

The application is built using a combination of modern web technologies that have been carefully chosen for performance, maintainability, and developer productivity. The frontend is implemented in TypeScript using the React library, version 18, and is built and served using the Vite development tool with the SWC plugin for fast compilation. The user interface uses the Tailwind CSS framework for styling, the shadcn-style component library built on top of Radix UI primitives for accessible interactive elements, the Lucide React icon library for vector icons, and the React Markdown library for rendering assistant responses that contain markdown formatting. Client-side routing is provided by React Router, version 6. Toast notifications are provided by the Sonner library. Local data fetching and caching utilities are provided by TanStack React Query.

The frontend server is a small Express application written in TypeScript and executed using the tsx runtime. It hosts the Vite middleware during development and serves the compiled static assets in production. The proxy layer is implemented using the standard Node.js http module, which forwards requests directly to the Python backend without any buffering. This direct approach was chosen over higher-level proxy libraries to guarantee that streaming responses are passed through to the client in real time.

The backend server is implemented in Python using the Flask micro-framework and the flask-cors extension for cross-origin support. Database access is performed using the psycopg2 library, which provides a direct synchronous interface to PostgreSQL. Communication with the artificial intelligence provider is performed using the official OpenAI Python software development kit. Environment variables are loaded using the python-dotenv library. The artificial intelligence model used by the system is OpenAI gpt-4.1-mini, which is accessed through the Replit-managed OpenAI integration using a managed application programming interface key and base uniform resource locator.

The persistent data layer is a managed PostgreSQL database provided by the Replit platform. The schema is defined using the Drizzle ORM library and is synchronized to the database using the Drizzle Kit command line tool. Two main tables are used by the application, namely the conversations table and the chat messages table, which are linked through a foreign key relationship. Universally unique identifiers are generated by the PostgreSQL `gen_random_uuid` function.

Supporting tooling for the project includes ESLint for linting, TypeScript for static type checking, Vitest for unit testing, Concurrently for running the frontend and backend processes together during development, and ESBuild for bundling the production server. Package management is handled by npm for the JavaScript portion of the project and by uv and pyproject.toml for the Python portion of the project.

## 7. Environment Variables

The application requires a small number of environment variables in order to operate correctly. All of these variables are managed by the Replit platform in the development and production environments and do not need to be supplied manually under normal conditions.

| Variable | Purpose |
|----------|---------|
| `DATABASE_URL` | The full PostgreSQL connection string used by both the Drizzle tooling and the Python backend. |
| `AI_INTEGRATIONS_OPENAI_API_KEY` | The application programming interface key used to authenticate with the OpenAI service through the Replit managed integration. |
| `AI_INTEGRATIONS_OPENAI_BASE_URL` | The base uniform resource locator used to address the OpenAI service through the Replit managed integration. |
| `PYTHON_PORT` | The internal port on which the Python backend listens. Defaults to port eight thousand. |
| `PORT` | The public port on which the Express frontend server listens. Defaults to port five thousand. |

## 8. Development and Operation

The application is started during development by running the `npm run dev` command from the project root. This command uses the Concurrently tool to start both the Express frontend server and the Python backend server at the same time, with their output prefixed and color-coded for clarity. The frontend server listens on port five thousand and is the public entry point of the application. The Python backend listens on port eight thousand and receives proxied requests from the frontend server.

The database schema is synchronized to the PostgreSQL database using the `npm run db:push` command, which invokes the Drizzle Kit tool. The production build is produced using the `npm run build` command, which compiles the frontend application using Vite and bundles the Express server using ESBuild. The compiled production server is started using the `npm start` command. Linting is performed using the `npm run lint` command, and unit tests are executed using the `npm test` command.

The application has been designed to operate reliably within the Replit hosting environment, including support for the platform's reverse proxy, host configuration, and managed integrations. It is fully responsive and has been verified to work on mobile devices, tablets, and desktop computers, with the layout adapting automatically to the available screen size.
